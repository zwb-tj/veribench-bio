# SAFETY · VeriBench-Bio

> **一句话立场**：本基准测的是**方法学判断力**（统计、设计、推断），
> **不是**任何可操作的能力。凡是能提高现实危害的题目一律不做，
> 不管它多容易构建、多有区分度。

- 版本：v1（2026-09）
- 状态：**未发布**
- 生物安全审阅者：**尚无**（见 §5，这是发布阻塞项）

---

## 1. 红线：明确不做的东西

以下类别**任何情况下都不进本基准**：

- 增强**传播力** / **致病性** / **免疫逃逸**的任何方法
- **毒素**合成或增强
- **select agents** 与受管控生物剂
- **基因驱动**
- **生殖系编辑**
- 任何**增强型（gain-of-function）**实验设计

这不是"暂时不做"，是**设计红线**。若将来某个题目落入这些类别，正确动作是**放弃该题**，
而不是"抽象化后保留"。

---

## 2. 只做的三类

本基准在生物安全维度上**只测**：

1. **拒答正确性**：面对越界请求，模型是否明确拒绝（而不是给出部分帮助）
2. **风险识别**：模型能否识别一段实验设计中的生物安全风险
3. **边界含糊性**：模型在被拒绝的边界上是否含糊其辞
   （例如用"理论上""在受控条件下"包装出可操作内容）—— 这是最值得测的一项

**上游依据**：
- 北京智源 2026-07 公开警示 LLM agent 的生物安全风险
- arXiv:2604.19811 将"**能力测量本身**"视为风险信号 ——
  这条直接影响了本项目的设计：**我们不发布能提升能力的题，也不发布能力排行榜以外的推断**

## 3. 实际执行情况（**照实说，包括没做的**）

| 措施 | 状态 |
|---|---|
| 高危题**抽象化**（去掉序列、菌株、剂量参数） | ✅ **当前 24 道 rubric 题全部属于方法学讨论**，不含序列/菌株/剂量 |
| 敏感子集 **gated release + canary string** | ⬜ **尚无敏感子集，因而未实现**。机制在 schema 里已就位（`safety_review` 字段的 `gated` 取值，审计器 R9 强制门控发布） |
| **≥1 名生物安全背景审阅者**签字 | ⬜ **无**。见 §5 |
| 审计器强制门控 | ✅ **已实现并有自检**：R8（`safety_review=rejected` 却标 public → 致命）、R9（`gated` 混入 public → 致命），`--self-test` 16/16 通过 |

**为什么"抽象化"这一条能勾**：当前 24 道题全部是**对已发表研究的方法学批评**
（混杂、伪重复、多重比较、幸存者偏倚、结论超出数据）。它们讨论的是"这个推断链哪里断了"，
而不是"怎么做这个实验"。**这不是因为我们刻意筛掉了高危题，而是因为题目类型本身就是方法学的。**

## 4. 数据层面的安全相关决定

- **T2 的变异解读题**：题面做了**结构去标识**（不含 HGVS / rsID / 坐标 / ClinVar ID /
  氨基酸改变）。这不只是防污染，也**降低了把条目当作临床建议的可能**。
- **不发布原始论文全文**：`rubric/items/sources/` 下的 27 篇 PMC 全文**不进公开仓库**。
  公开的是改写后的题目，不是别人的论文。
- **不含受控数据**：无 dbGaP / EGA / 需 IRB 或 DUA 的数据。
  `contains_restricted_data` 在全部台账条目中为 `false`（审计器 R3：为 true 则不得公开）。
- **人类数据逐条裁决**：27 篇来源的 `contains_human_data` 逐篇判定并写出依据
  （`rubric/items/human_data_basis.json`），**不再允许裸布尔**（审计器 R12）。
  教训：此前 27 篇被一律标成 `true`（含蜜蜂转录组、大鼠模型、叙述性综述），15/27 是错的。
