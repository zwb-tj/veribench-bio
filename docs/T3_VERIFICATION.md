## 二、❌ 发现的问题（1 条 — 定义漏洞，非实现错误）

### 问题 1：`atom_count` 在多 model（NMR）结构上**口径歧义**

**发现经过**：我用 RCSB Data API（**与生成真值的通路不同**）做交叉核对，
发现只有 1/8 相符。逐条查下去：

| 条目 | 我们 ATOM | API `deposited_atom_count` | 解释 |
|---|---|---|---|
| 1CRN | 327 | 327 | 相符 |
| 1UBQ | 602 | 660 | API 的 660 = ATOM 602 + HETATM 58（**口径含 HETATM**）；我们的 `hetatm_count=58` 恰与 API 的 `deposited_solvent_atom_count=58` 一致 |
| 2GB1 | 855 | 436 | mmCIF 的 855 = API 的 436 + `deposited_hydrogen_atom_count` 419（**mmCIF 含氢原子，API 字段不含**） |
| **1L2Y** | **11,552** | **154** | ⚠️ **38 个 NMR model** —— 我们的计数是**全部 model 之和**，API 只算一个 |

**结论**：
- 前两种不符是**口径差异**（我们与 API 数的是不同的东西），**不是我们错**
- **第三种是真实缺陷**：题面没有规定"算几个 model"。
  一个按常规理解作答（只算一个 model，154）的人**必然答错**，
  而且**无从知道**我们对齐的是哪种口径 —— 判定权在我们，他没得辩

**影响范围**（实测）：题池 20 条中**只有 1 条**（`1L2Y`）是多 model 结构。
另外 19 条无歧义。

**严重度**：**medium**。不是数据错误（计数本身是对的），
是**题面定义不完整**，会让一道题的作答者被不公平地判错。

**建议的修法**（留给后续修复，本任务只报告不修）：
1. 题面明确写"统计**全部 model** 的 ATOM/HETATM 行"——最省事，且与现有真值一致；
2. 或者把 `1L2Y` 换掉，题池只收单 model 结构；
3. 或者增加一个 `model_count` 判分量，把"多 model"从陷阱变成考点。
**推荐 (1)**：一处措辞即可，不动数据、不改真值、不影响已通过的测试。

## 三、⬜ 无法在当前环境验证的项（照实说）

| 项 | 为什么验不了 |
