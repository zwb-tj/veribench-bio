## 二、❌ Findings（2 条，均为 CI 阻断，已修）

### F1（severity: high）`check_publishable_agree.py` 在全新 clone 里**误报失败**

**位置**：`scripts/check_publishable_agree.py`（我上一轮自己写的守卫）

**问题**：它通过**抓取三个消费方的 stdout** 来数文件数。
但在全新 clone 里，`verify_no_answer_leak.py` 会因缺轮换池数据而**正确地 SKIP**，
于是不打印任何计数 → 我的检查器报「数不出文件数（输出格式变了？）」→ **失败**。

**实测证据**（clone 里）：
```
各消费方数出的文件数：
     732  scripts/print_project_stats.py
    None  scripts/verify_no_answer_leak.py
     731  scripts/scan_secrets.py
❌ 『什么算会被发布』出现了第二份实现 / 已经漂移：
  · scripts/verify_no_answer_leak.py: 数不出文件数（输出格式变了？）
```

**为什么严重**：它把**一个完全正常的 SKIP 误报成"实现漂移"**。
而 CI 变红之后，人的反应是**把检查关掉** ——
本项目已经吃过两次这个亏（`check_annotation_blinding.py` 误报 `model` 字段也是同一类）。

**requiredFix**：判据改为**直接导入各模块、调用它自己的 `publishable()`**，
而不是比较日志格式。要问的问题是「它们是否共用同一实现」，不是「日志长得像不像」。

**状态**：✅ 已在 `aa4a771` 修复。验证：本机与 clone 均通过。

### F2（severity: high）`print_project_stats.py --self-test` 在全新 clone 里**失败**

**位置**：`scripts/print_project_stats.py`（同样是我上一轮自己写的）

**问题**：它的断言**无条件**依赖 T1/T2 的**生成物**：
```
❌ T1 六次实跑  → 0
❌ T1 得分唯一 0.84655  → []
❌ T2 4726 条  → None
❌ T2 金丝雀 1181  → None
```
但 `_runs*` 与 `tasks/T2/data/items.jsonl` 都是**生成物且被 gitignore**，
全新 clone 里本来就不存在 → `--self-test` 失败 → `run_all_checks.py` 报「共 1 项失败」。

**为什么严重**：与 F1 同一类 ——
**把"这里没有这个产物"误报成"检查失败"**，而后果同样是检查被关掉。

**requiredFix**：区分两类断言：
- 只依赖**已提交**文件（发布集 / 检查步数 / 台账 / rubric）→ 无条件
- 依赖**生成物**（T1 `_runs*` / T2 `items.jsonl`）→ 有才断言，没有就**显式打印 SKIP**

**状态**：✅ 已在 `2f077a3` 修复。
**验证**：clone 里 `run_all_checks.py` **exit=0，零 ❌**。

### 补充：T3 自身的缺陷（来自 t4，非本审查发现，但必须进结论）

**F3（medium，未修）**：`atom_count` 在多 model（NMR）结构上**口径歧义**。
`1L2Y` 有 38 个 model，我们报 11,552（全部 model 之和），RCSB API 报 154（单 model）。
题面**没有规定算几个 model** → 按常规理解作答的人必然答错，且无从知道我们对齐哪种口径。
影响范围实测：题池 20 条中**仅 1 条**。

**requiredFix（建议）**：题面明确写「统计**全部 model** 的 ATOM/HETATM 行」——
一处措辞，不动数据、不改真值、不影响已通过的测试。
（另两个选项：换掉 `1L2Y`；或增加 `model_count` 判分量把陷阱变考点。）

## 四、流程异常（影响本审查可信度，必须记录）

**AgentTeams 调度器自计划批准后从未产生任何成员会话。**

- 5 名成员（scope / datasource / builder / verifier / reviewer）**始终** `idle/unspawned`
- `t1`–`t5` 的尝试计数累计到 **attempt 2–5**，仍无 spawn
- 经用户**两次明确要求"继续"**，由**队长接管**完成 t1 / t2 / t3 / t4 / t5

**后果**：`t3`（实现）、`t4`（验证）、`t5`（审查）**由同一执行者完成** ——
本应三方分离的质量门禁**退化成自己查自己**。

**这一点必须让读者知道**，因为它直接决定了本报告能证明什么、不能证明什么。
