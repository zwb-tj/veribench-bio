# 用湿实验的话说明白：这个项目到底在干什么

> 这份文档写给湿实验背景的人。目标：读完你能明白我们在造什么、为什么这么做、以及**你在这个项目里能干哪些 AI 干不了的事**。

---

## 1. 一句话

**我们在给"AI 读文献 / 做生信分析"这件事造一套校准品。**

就像你拿到一台新仪器，不会直接信它的读数——你会先跑一批**已知浓度的标准品**，看它准不准、稳不稳。
现在满世界都在说"某个 AI 模型生物学很厉害"，但**没有人造过一套真正可信的标准品去测它**。

我们造的就是这套标准品：**答案已知的干实验任务**，加上公开的评分规则，用来测各种 AI 到底靠不靠谱。

---

## 2. 先建一套翻译表：湿实验概念 ↔ 我们这个项目

| 你熟悉的东西 | 我们项目里的对应物 | 说明 |
|---|---|---|
| 标准品 / 校准品（已知浓度） | **真值（ground truth）** | 题目的正确答案 |
| 室间质评 EQA / 能力验证 PT | **benchmark / 评测集** | 大家一起跑同一套题，比谁准 |
| 待验证的仪器 | **LLM / AI agent** | 它可能很准，也可能自信地胡说 |
| 你的实验记录本（试剂批号、厂家、收货日期） | **provenance ledger（溯源台账）** | 每道题用了什么数据、什么许可、谁核的 |
| MTA / 材料转移协议 | **数据许可（license）** | 决定你能不能把数据给别人、能不能商用、能不能改 |
| "未检出" vs 硬编一个数值 | **abstention（弃答）** | 不知道就说不知道，而不是编 |
| 两位老师独立判读、算一致性 | **双标注 + Cohen's κ** | 衡量两个裁判（或两个 AI 裁判）有多一致 |
| 复孔 / 重复性 | **可复现性** | 同一个镜像跑两遍，分数应该一样 |

## 3. 为什么"许可"是这个项目的头号风险——用 MTA 来理解

你要用别人实验室的质粒，得先签 MTA。MTA 会写清楚三件事：**能不能商用、能不能改造、改造后要不要也开放**。

数据集有完全一样的东西：

| 数据许可 | 相当于 | 我们能用来做公开题库吗 |
|---|---|---|
| **CC0** | 公共领域，随便用，连致谢都不强制 | ✅ 可以 |
| **CC BY** | 能用，但必须写明出处（"用了要致谢"） | ✅ 可以 |
| **CC BY-NC** | **仅限学术，不得商用** | ❌ 不行（"仅限研究用途"） |
| **CC BY-ND** | 能用，但**不得改造** | ❌ **不行** |
| **CC BY-SA** | 你改造后的东西**必须同样开放**（传染） | ❌ 不用（会把我们整套题库拖成同一种许可） |

**最容易踩的一个坑**：很多人以为"CC BY-ND 只是要求署名、别改"就够了。但**"把论文内容写成一道考题"这件事本身就是"改造"**。所以 ND 对我们等于**完全不可用**，不是"标注一下就行"。

这就是为什么我们**写了一个自动卡控脚本**（`scripts/audit_licenses.py`），而不是在文档里写一句"请注意许可"。就像 QC 要有卡控规则，不能靠人记得——现实教训是:有个很有名的大学生信评测集，做了 52 万条题，最后发现**只有 35 万条能公开**，剩下的因为来源许可受限只能烂在硬盘里。

**另一个坑**：很多人以为 arXiv 上的论文都是"开放获取随便用"。**不是。** arXiv 的默认许可是"作者保留权利、限制任何形式的再使用"，只有**元数据**是 CC0。所以我们不能把 arXiv 当安全区，必须逐篇查许可。

## 3.1 软件的许可又是另一套，而且它管的是"分发"不是"使用"

数据许可管的是"**我能不能用这份数据**"；**软件许可管的是"我能不能把这份软件交到别人手里"**。

对我们这个项目，这个区别是决定性的：我们要发布一个 **Docker 镜像**——相当于把一整套"试剂盒"打包送出去。镜像是**分发行为**，所以：

- 某个工具**我们自己跑**，没问题
- 但只要它**在镜像里**，就是在分发它，**义务跟着来**
- **哪怕镜像里那段代码根本不会被调用**，义务**依然存在**

→ 用你的话说：**你可以用某个试剂做实验；但你要把它分装进试剂盒送给别人，授权范围是另一回事——而且和你用不用它无关。**

**GPL 和 LGPL 也不是一回事**：

| 许可 | 相当于 | 我们的政策 |
|---|---|---|
| **GPL / AGPL** | 你分装了，你的**整个试剂盒**都必须同样开放 | ❌ 禁止 |
| **LGPL** | 可以分装，但必须提供原料来源、允许别人**替换那个部件** | ⚠️ 允许，但必须附合规材料 |
| MIT / BSD / Apache | 署名即可 | ✅ 随便用 |

**实测结果比预想的更有意思——它推翻了我们自己的判断两次**：

我们原以为"用 GATK4 就没问题"（它是 Apache-2.0）。拆开它的 jar 一看：

- 里面**确实打包了 BWA 的代码**（`libbwa.so`，74 万字节）
- 还有一个库**静态链接了 libuuid**（静态链接通常比动态链接麻烦）

按第一版判断，这两条都是"GPL 传染"，得赶紧删。但**逐文件核验源码头之后，两条全翻了**：

| 我原先以为 | 实际是 |
|---|---|
| 打包的是 **GPLv3 的 BWA** | 那个被 pin 住的版本**是 Apache-2.0**（上游换过许可，v0.7.17 之后才回到 GPLv3）—— **是上游自己管理混乱** |
| libuuid 是 **LGPL** | **是 BSD-3**（GenomicsDB 自己的 LICENSE 写错了，把 BSD 写成 LGPL） |

→ 所以这两个**都不构成"传染"问题**。真正的问题是**没署名**：里面装着 74 万字节的代码，却**一个字都没提它来自谁**。这违反的是 Apache/MIT 的**署名义务**，不是 GPL。

**而真正的风险，是在完全没想到的地方找到的：**

1. **`htsjdk` 这个依赖在撒谎**：它的元数据只写 MIT，但里面有 **22 个文件实际是 LGPL**，而且**真的会被用到**（我们用 `--dbsnp` 这类参数时的必经之路）。**删不掉。**
2. **`jgrapht` 是"LGPL 或 EPL 二选一"**——上游明确写了"由被许可方选择"。**我们可以主动选 EPL，直接绕开 LGPL 的麻烦。** 这是整个审计里最省事的一个发现。
3. **最严重的根本不在 GATK 里，在它的运行环境（conda）**：
   - **Intel oneMKL 是专有闭源数学库**——**源码拿不到**，比 LGPL 严重
   - **R 和 GSL 是真 GPL**（连编译器二进制都有）

→ **解法：不用官方的环境，自己写一份 Dockerfile——把 R 去掉、数学库从 MKL 换成开源的 openblas。** 专有组件和 GPL 同时消失，镜像体积还能小一大截。

**还有一个必须记下的逻辑坑**：我们政策里写的"镜像内不得含 GPL"——**按字面根本做不到**。因为 Ubuntu 镜像里的 `bash`、`sed`、`tar`、`grep`、`make` **本身就是 GPL**。所以这条政策只能理解成"**不得含与我们应用构成一个整体、或我们依赖其核心功能的 GPL 组件**"。**这需要跟法务确认语义**，否则规则没法执行。

**"看起来没问题、拆开才发现有问题"在这个项目里已经发生四次了**（前三次是 lit-radar 的空白判断、arXiv 是"安全区"、vcfeval 是"非商用"）。
所以我们的做法是：**每个交付物都真的拆开验一遍，不信任何自我声明**——不信上游 README，**也不信依赖清单里写的许可**（htsjdk 就是活例子）。

**顺便说：因为这个发现，我们最后的决定是——干脆不用 GATK 了。**
改用 **FreeBayes**（MIT，我亲手读了它的 LICENSE 原文）+ **samtools / bcftools**（MIT）+ **hap.py / vcfeval**（都是 BSD，也都亲手读过）。这样整条链路**零 copyleft**，上面那些麻烦**一次性消失**，镜像还小得多——而**镜像小、跑得快，正是我们"任何人都能复现"这个卖点的前提**。

**这背后是一条更一般的原则：当"合规负担"和"更简单的方案"摆在一起时，选更简单的方案。** 少一个依赖，就少一个将来会爆炸的地方。**这个项目里我们更愿意少要一点功能，也不愿意留一个说不清的地方。**

## 4. 八道题分别是什么（用湿实验语言）

### T1 变异检出 —— 我们的"主力标准品"
**给它什么**：一个样本已经比对好的测序数据（BAM 文件，相当于"reads 已经贴回参考基因组了"）。
**让它干什么**：找出这个样本哪里有变异（SNP / 小插入缺失）。
**答案哪来的**：**GIAB 的 HG002 标准品**。这是 NIST 做的人类基因组标准品细胞系，真值经过多个实验室交叉验证——**和我们用标准品校准仪器是一模一样的逻辑**。

⚠️ 这里有个非常"湿实验"的细节：**我们原本想用 HG001（也就是老牌的 NA12878），但查下来它不行**。原因是 HG002 那几个样本在知情同意里**明确写了同意商用再分发**，而 HG001 是更早的 HapMap 来源，**同意范围没写清楚**。
→ 这就像**样本的知情同意范围决定了你能不能用它、能不能给别人**。数据本身是公开的，瑕疵在同意书。

### T2 变异解读
**给它什么**：一段变异的证据描述（**不是**直接给变异名让它背答案）。
**让它干什么**：判断这个变异是致病还是良性。
**答案哪来的**：ClinVar 里高置信度的条目（只取 3–4 星，1–2 星证据太弱）。
⚠️ **这题最大的风险是"泄题"**——ClinVar 是公开数据库，模型很可能**已经把答案背下来了**，就像学生做过原题。所以规则是：**只用模型训练时间截止之后才提交的新条目**，用时间做切分。

### T3 / T4 结构 / 功能注释
- **T3**：PDB（蛋白结构数据库，CC0）—— 相当于"结构生物学界的公共标准品库"
- **T4**：GO（基因功能本体，CC BY）—— 相当于"功能注释的标准术语表"

### T5 宏基因组物种组成
**给它什么**：一份测序数据。
**让它干什么**：算出样本里各物种的比例。
**答案哪来的**：**CAMI2** 标准数据集——相当于**"成分已知的人工菌群模拟样本"**，用来测"你测出来的菌群比例准不准"。

### T6 直系同源聚类
**答案哪来的**：QfO 标准。

### T7 转录本定量 / T8 差异表达 —— 这两题我们做了一次"诚实降级"
查下来这两题**不存在权威真值**。原来的打算是拿"已发表论文里的结果表"当真值，但那些结果本身依赖作者当时的工具版本和参数，**不是真正的"标准品"**。

**我们决定不假装它是准确率题。** 处理方式：
- 明确标注真值类型是"**参考实现的输出**"，不是"权威真值"
- 只问"你的结果和参考实现一致吗"，这叫**可复现性**，不叫准确率
- 它们在榜单上**单独一个分区**，**绝不和 T1–T6 的准确率混在一起排**

→ 用湿实验的话说：**这两题我们没有标准品，只能做复孔一致性。那我们就老老实实说这是一致性，不说这是准确性。** 而且这条规则**写进了代码**（审计器 R10/R11 会强制拦截），不是靠自觉。

## 5. 为什么一定要"30 分钟内、只用 CPU"

这不是技术炫技，是**用途决定的**：

如果跑一次评测要 24 小时、还得排队等 GPU 集群，那这套题**只有大厂实验室用得起**，别人根本不会碰——**那它就失去了"第三方可以复核"的意义**。

30 分钟 CPU 意味着：**任何人在自己的笔记本上就能跑一遍，自己验证我们的榜单是不是真的。**
→ 相当于**诊断试剂要能在普通实验室做，不能只在中央实验室做**。

**代价要明说**（这也是我们会写进数据卡的）：
为了压进 30 分钟，T1 **只做 chr20 上 10–12 Mb 这一段，而且把"比对"这一步预先做掉了**。
也就是说：**它只考"找变异"，不考"比对"**。这是刻意缩范围，不是我们做不到——把话说清楚，比让用户以为"它能测全流程"要诚实得多。

**被砍掉的两道题**（同样是诚实的结果）：
- ❌ Micrococcus 直系同源聚类
- ❌ Cuatro Ciénegas 物种组成
**两题都找不到权威真值 → 直接砍掉，不硬凑。** 宁可少几道题，也不做一道"答案是我们自己算的"题——**那就成了自己出题自己判卷**。

## 6. 什么是 κ（kappa），为什么它可能比分数本身更重要

题库里有一部分是**开放题**——像写审稿意见那样，没有唯一标准答案。这种题只能用 AI 当裁判来打分。

那问题就来了：**AI 裁判自己可信吗？**

**κ 就是衡量"两个裁判一致性"的数字。** 相当于**两位病理医生独立看同一批片子，他们的判断一致的比例有多高**。

逻辑很直接：
- 如果**两个人类专家自己都不一致**（κ 很低），那 AI 打出来的分数就**没有意义**
- 如果 AI 裁判和人类专家一致性很差，那这张榜单就**不可信**

**而现在整个领域几乎没人公开报 κ。** 大家只报分数，不报裁判可不可信。
我们把 κ 做出来、把 AI 裁判判错的案例也公开——**这就是我们的差异化，成本不高，但没人做。**

## 7. "污染"是什么（用学生的比喻）

就像**学生考前做过原题**。

如果题目来自一个公开了很多年的数据库，模型很可能**已经把答案背下来了**。这会让它看起来很强，但它**不是"会做"，是"记得"**。

对策（三条一起上）：
1. **时间切分**：只用模型训练截止之后才出现的数据
2. **程序化生成**：能参数化生成的题就生成，可以无限换版本
3. **留 20% 不公开**：如果有人在公开部分刷到很高、在私有部分掉下来，说明是过拟合

每个题的污染风险我们已分级：**ClinVar 解读极高、差异表达高、定量中、变异检出低、宏基因组低、PDB/GO 低**。高风险题必须做时间切分。

## 9. 你（湿实验背景）在这个项目里能干 AI 干不了的事

这一点很重要：**这个项目缺的恰恰不是写代码的人，而是能判断"这在实验室里成不成立"的人。**

| 你能做的事 | 为什么 AI 替代不了 |
|---|---|
| 判断一道题**在真实实验里有没有意义** | AI 分不清"能算"和"该做" |
| **写开放题的评分标准（rubric）** | 需要真实的实验判断力，不是文字能力 |
| 当**双标注的第二位标注者**，一起算 κ | κ 必须有两个独立的人 |
| **审生物安全红线** | 哪些题涉及两用风险（增强致病性、毒素、select agents），需要专业判断 |
| 判断"模型给的答案**实验上可不可行**" | 比如试剂浓度、离心条件在实操上是否离谱 |
| 判断**题目难度是否贴近真实工作** | AI 生成的题常常"教科书化"，不贴近台面 |

**换句话说：AI 负责规模，你负责可信。而这个项目的全部卖点就是可信。**

## 10. 附：干实验黑话 → 湿实验翻译表

| 黑话 | 翻译 |
|---|---|
| reads | 测序读段（测序仪一次读出来的短序列） |
| 比对 / align | 把 reads 贴回参考基因组，确定它来自哪里 |
| BAM | 比对结果文件（reads + 位置） |
| VCF | 变异列表文件（"哪个位置、从什么变成什么"） |
| SNP / indel | 单碱基替换 / 小片段插入缺失 |
| 参考基因组 (GRCh38 等) | 标准参照序列，相当于"标准曲线" |
| **真值 / ground truth** | **标准品的已知答案** |
| benchmark | 评测集 / 能力验证盘 |
| **benchmark 污染** | **泄题，模型背过答案** |
| F1 / 精确率 / 召回率 | 综合准确度指标（F1 兼顾"漏检"和"误检"） |
| **abstention / 弃答** | **不报假值，而是说"原文/数据里没有"** |
| provenance | 溯源（这东西从哪来、经过什么加工） |
| **Docker 镜像** | **一个封装好的实验环境，别人拿去就能原样跑** |
| manifest / hash | 清单 + 指纹（证明文件没被偷改过） |
| leaderboard | 排行榜 / 成绩公示 |
| κ (Cohen's kappa) | 两个判读者之间的一致性（0 = 完全靠猜，1 = 完全一致） |
| **CPU-only** | **不需要 GPU 和集群，普通电脑就能跑** |

## 11. 记住这三句就够

1. **我们在造标准品**：答案已知的干实验任务，用来校准"AI 做生物学"这件事。
2. **可信比规模重要**：所以只敢用 CC0 / CC BY 的数据、只敢用权威真值、没有真值的题宁可砍掉或降级成"复现性"。
3. **最难的不是写代码，是判断**：判断这题在实验上成不成立、这答案可不可信、这红线能不能碰——**这正是你的价值。**
