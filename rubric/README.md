## 为什么这是第二支柱（竞品尽调结论）

榜单若用 LLM judge 打分却**不报一致性**，整张榜都不可信。
而当前生态的普遍缺陷正是：**要么不发榜，要么用 judge 但不报 κ**。

> 这一格已核实为**空白** —— 见 `../research/DECISION.md`。

## 核心方法学主张（本项目认为最容易被引用的一点）

> **人类之间的 κ 是 LLM 裁判可靠性的上限。**

如果两位人类标注者自己只有 κ=0.55，那么 judge 达到 0.55 就已经"到顶了"。
此时：
- 说"judge 不够可靠"是**不公平的**
- 只报"judge 与人类一致性 0.6"是**假精确**

所以本支柱**一律报三个数**：**人类上限 / judge 绝对值 / judge 相对上限的比例**。

## 三层工作流

```
① 双盲标注        ② 分歧仲裁           ③ judge 元评测
A、B 各自独立打分  →  人工解决 A≠B  →   judge 对金标准，算相对上限 + 偏差 + 失效案例
（互不可见）         得到**金标准**       （金标准是唯一合理的比较基准）
```

**没有仲裁文件时会退化**为"仅用 A==B 的条目作金标准"，并**如实报出被排除的比例**
—— 这个比例本身就是"rubric 写得清不清楚"的指标。

## 三个必须一起报的量（缺一个都不够）

| 量 | 为什么不能省 |
|---|---|
| **未加权 κ** | 严格一致 |
| **加权 κ（线性/二次）** | 评分是**有序**的（0/1/2），"0 vs 2"比"0 vs 1"严重得多。但 ⚠️ **加权 κ 并不总是更高**——当分歧集中在跨两档时它反而更低（已固化为自检案例）。**所以两个都必须报，只报一个会误导** |
| **自助法 95% CI** | **只报点估计是弱证据**。κ=0.6 在 n=30 与 n=500 上可信度天差地别。CI 用**固定种子**，可复现 |

## 已验证（用夹具跑通整条链）

```
人类上限（二次加权 κ） = 0.8415   95% CI (0.7737, 0.8982)
judge vs 金标准        = 0.7091   95% CI (0.5929, 0.8141)
**相对上限 = 0.8427 → 接近人类上限**
偏差：偏松（均值 +0.2333）  完全命中率 0.725
失效案例：33 条（差1档 28，差2档 5）
```

**这个例子恰好演示了核心主张**：judge 的 0.7091 单看很平庸，
但**相对人类上限 0.8415 达到了 84%** —— 不报上限就会错误地判它不可靠。

夹具还验证了：
- ✅ 双盲标注表生成 + 完整性校验
- ✅ **校验器拒绝静默放过**（1 条未填 + 1 条非法 → 直接失败，不当成 0）
- ✅ 失效案例被收集并带出题目/标准/锚点，可供人工复盘
- ✅ 仲裁文件被正确用作金标准

## 预检规则的修正（跑自己的夹具时发现的）

第一版把"题干含结论词"当**硬问题**，结果夹具里「变异**致病**性判读」这种**合法主题词**也被拦了。

对**开放题**而言，问"你会如何判断它是否致病"是正当的问题，不是暗示题。
所以修正为：

| 检查项 | 级别 | 理由 |
|---|---|---|
| **身份泄露**（DOI / PMC ID / HGVS / accession / rsID / 坐标） | **硬拦** ✅ | 能让模型顺着查原文，属结构性泄露 |
| **结论词** | **警告** ⚠️ | 可能是问题的一部分，也可能是答案 —— **需人工确认** |

> 教训与项目其它部分一致：**规则要区分"结构性错误"与"需要人判断的模糊情形"**，
> 把后者当硬拦会产生大量误报，最后人就会习惯性忽略所有告警。

## 为什么有 `run_all_checks.py`（一个反复踩的坑）

我在中文文本里混进 ASCII 双引号这个错，**已经犯了七次**。
这类错误只有真正编译那个文件时才暴露 —— 而手跑 `py_compile` 是我临时想起来的，
**不该靠记得**。所以固化成一条命令：

```bash
python3 run_all_checks.py     # 10 个环节，任一失败则非零退出
```

环节：① 语法编译 ② **中文串引号自检** ③ 各脚本自检 ④ judge I/O 链（期望失败）
⑤ 主台账门禁 R0–R12 ⑥ 事实字段裁决核验 ⑦ 区分度 ⑧ v1.0↔v1.1 对照
⑨ 分歧边界与量表粒度 ⑩ **锚点事实可判性 + 正式版 v1.2**

> 与本项目其它部分同一个模式：**把"我记得要检查"变成"机器一定会检查"**。
> 而这一轮补上的教训是：**机器检查只能发现"我写错了"，发现不了"我的检验错了"**——
> 后者要靠**对照组**（见 `../SPEC.md` §13.3k）。
