# rubric v1.1 改写规则

> 依据：`RUBRIC_V1.1_REVISION_LIST.md`（18 条实测确认缺陷 + 6 类结构缺陷模式）。
> 本文件只讲**怎么改**，不讲为什么——为什么见改写清单。

## 一、必改的六条规则

### R1. 2 分锚点不得是"且"串起来的合取清单

**问题**：`2 分 = 指出 X 且说明 Y 且给出 Z`，而 `1 分 = 笼统提到`。
最常见的那类回答（**切题具体、但缺 1–2 个子要件**）没有锚点描述它，
裁判只能按"不确定给低分"压到 1。这是稳定性损失的头号来源（9/12 裁判独立提出）。

**改法**：2 分锚点写成**一个核心论断** + `至少 M 项`（M ≤ 2），其余降为举例。
```
✗ 2 分 = 指出 A、B、C、D 四项且未做等效剂量匹配
✓ 2 分 = 明确指出归因不成立这一核心论断，并至少给出两项具体理由（如 A、B；C、D 亦可）
```

### R2. 每条标准的判定不得依赖题面里没有的事实

**问题**：锚点把**题面未交代**的事当作得分要件（如"更正说明未展示原始数据"，
但情景从未说更正说明里有什么）。这类档位**不可判**。

**改法**：删掉题面推不出的要件；若该要件确实重要，把它**补进题面**再要求。

### R3. 1 分锚点用正面描述，不用否定式清单

**问题**：`1 分 = 提到 X 但未说明 Y、也未涉及 Z`。回答若提到了 Y，这锚点字面就不适用。
**改法**：`1 分 = 提到了该议题，但没有点出具体缺陷/机制/后果`。

### R4. 跨标准不得重复计分

**问题**：同一句回答同时满足两条标准（如"安慰剂效应"同时算进 c1 与 c4），
协议没规定能否双记，裁判各判各的。
**改法**：在标准文本里写明该断言的归属（`注：安慰剂效应计入 c4，本条只看无对照设计`）；
两条确实重叠时**直接合并**。
**特别注意**：`c1（最薄弱环节）` 与 `c4（只补一项实验）` 常把同一个实验算两次。

### R5. "若只能补做一项实验"必须给部分分

**问题**：0 分锚点＝"未给出任何单一实验选择"。回答列了 3–4 条**都合理**的建议
但没收敛到一项，一律记 0；而同样内容在 c3 能记 1。
**改法**：三档改为
- `0` 未给出任何实验方向 / 方向与最薄弱环节无关
- `1` 给出了合理方向，但**未收敛为单一实验**，或缺关键设计（对照/读出/剂量）
- `2` 收敛为**一项**实验，直接针对最薄弱环节，且给出可执行的对照与读出

### R6. 枚举式锚点改为"至少 M 项"

**问题**：2 分锚点要求同时枚举 N 项（如"浓度、时长、起算时点、累积剂量"四项），
抓不到 N 项的实质正确回答被字面降档。
**改法**：`至少 M 项`（M ≤ 2），其余写成"如…"。

## 二、逐条必改清单（18 条）

|---|---|---|---|

| R-0016 | c4 | 反向 | [1,0,1] · [1,0,1] |

| R-0020 | c2 | 饱和 | [2,2,2] · [2,2,2] |
| R-0020 | c3 | 饱和 | [0,0,0] · [0,0,0] |
| R-0020 | c4 | 反向 | [1,0,1] · [1,0,1] |
| R-0021 | c3 | 反向 | [0,1,1] · [1,1,1] |
| R-0023 | c1 | 反向 | [2,2,1] · [2,2,1] |
| R-0024 | c3 | 饱和 | [1,1,1] · [1,1,1] |

两种类型的处理**不同**：

- **饱和 = 恒为 2**（白送分）→ 该标准太容易，或它问的东西所有答案都会写。
  提高门槛：要求**具体的机制/量化后果**，而不是"提到了就算"。
- **饱和 = 恒为 0**（无人能得）→ 该标准**不可达**：要么题面推不出、要么锚点自相矛盾。
  按 R2/R3 修，或**整条删除**。
- **饱和 = 恒为 1** → 三档都不满足 2、又都超过 0。通常正是 R1 的合取病：
  把 2 分锚点拆成"核心论断 + 至少 M 项"。
- **反向** → 先按 R1/R3/R4 检查是否合取病或跨标准重复；修完仍反向的，
  说明**该标准考的不是区分好坏答案的维度**，应**删除**。

## 三、不可改动的部分

- `item_id`、`question`、`context`、`provenance`、`safety_review` **一个字都不能动**
- 标准**数量**尽量保持不变（`criterion_id` 序列不变）；确需增删时在 `revision_note` 里写明
- 每条标准仍必须**可判定**：换一位专家来打能得到同一个分
- 锚点仍必须是 `"0"`/`"1"`/`"2"` 三档，且**必须切得开**

## 四、每条改过的标准要写 `revision_note`

一句话说明**改了什么、为什么**，例如：
`"原 2 分锚点为四项合取，按 R1 改为『核心论断 + 至少两项』"`。
没改的标准不写这个字段。

## 五、输出

- 每条标准新增可选字段 `revision_note`（字符串）
- 题目顶层新增 `rubric_version` = `"1.1"`
- 写出到 `items/items_v1.1.jsonl`（**不要覆盖** `items.jsonl`）
