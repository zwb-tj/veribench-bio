# 这一轮发生了什么 · 以及现在需要你做什么

> 写给湿实验背景的人。术语先翻译，再讲事。

---

## 一、先讲个类比（这是整套设计的核心）

你在实验室判读一张免疫组化切片，会怎么做？

不是"我觉得阳性"，而是先定标准：**细胞膜着色比例 >10% 记 1 分，>50% 记 2 分**。
然后——**同一个标准给两位病理医生看同一批片子，他们的一致率是多少？**

这个一致率就是天花板。因为：

> **AI 判读再准，也不可能超过两位人类专家之间的一致上限。**

如果两位病理医生对同一张片子只有 70% 一致，那任何声称"AI 判读准确率 85%"的说法都是
无意义的——那 15% 的差距根本不是 AI 的功劳，而是**标准本身没有唯一答案**。

我们这个第二支柱（`rubric/`）做的就是这个：

| 免疫组化类比 | 项目里的对应 |
|---|---|
| 判读标准（>10% 记 1 分） | **rubric**：每题 4–5 条标准，每条 0/1/2 三档 |
| 两位病理医生各自判读 | **双盲人工标注**（标注者 A / B） |
| 两位医生一致率 | **人类天花板 κ**（human ceiling） |
| AI 病理辅助系统判读 | **裁判模型**（judge） |
| AI 与专家一致率 ÷ 医生之间一致率 | **相对天花板比值**（本项目只报这个，不单报绝对准确率） |

**为什么必须是你来标？** 因为天花板必须由**两个真人**产生。
我一个 AI 去当其中一个标注者，那天花板就变成了"AI 与人类的一致性"，
整个方法论就塌了——那就成了自己给自己打分。

## 二、这一轮我做了什么（可以跳过）

三件事：

**1. 把第二支柱的主题并进了主台账。**
之前 rubric 题有自己一套溯源，主台账的许可门禁（R0–R11）**管不到它**——
等于一个项目里有两套"什么算合规"。现在并进去了，rubric 题和 T1/T2 走同一道门。
结果：**0 条致命违规，24 条警告**（警告都是"还没人工复核"，见下）。

**2. 逮到一个我自己犯的错，而且是被别人逮到的。**

`contains_human_data`（是否涉及人类个体数据）这个字段，
`candidates.jsonl` 里 **27 篇全填了 `true`**——包括：

- 一篇**蜜蜂**脑转录组研究
- 一篇**大鼠**心梗模型
- 好几篇**叙述性综述**（本身没采集任何数据）

**过半是错的**（15/27）。而 24 道题的溯源又是照抄它的，于是错误被复制了整个下游。

更糟的是**我写的校验脚本把这个错误冻结住了**：它强制"题目必须和 candidates 一致"，
有人想把错的值改成对的，脚本会报**"禁止编造"**。纠正一个错误事实，反而被拦下。

**3. 修法（三处一起动，缺一不可）**

| 改动 | 为什么 |
|---|---|
| 逐篇重判，加 `human_data_basis` 字段（5 个枚举值） | 裸的 true/false **没有任何可核对的痕迹**，所以它错了不会有东西报警 |
| 审计器加 **R12**：必须有依据，且依据要和布尔值自洽 | 让这个字段**第一次真正有牙齿**（此前它被声明必填却从未被使用） |
| `precheck` 把字段分两类：**许可判定**（强锁）/ **事实判定**（核对裁决文件） | "一致性校验"只能传递**已经验证过**的事实，不能把上一版数据当标准答案 |

修完做了**反向测试**：把蜜蜂那题改回错误的裸 `true`，审计器**立刻判失败**（R12）。
——"通过"不算证据，**"能拦住错误"才算**。

**4. 一个我自己的错误被出题子agent 揪出来**

我把 PMC11900006 判成了"含人类受试者数据"，理由是正文里出现了
"糖尿病视网膜病变患者血浆瓜氨酸/精氨酸"。

子agent 指出：**那段是引言在引用作者既往的工作 [5]，本文自身用的是商品化人视网膜内皮细胞。**

它是对的，我错了。用完整的**标题**复核全部 27 条后才确认：
标题写的是 *"…in Retinal Endothelial Cells"*——一篇体外细胞研究。

**教训**：源文有 24/27 篇被截断在 20,000 字符，我是在不完整文本上做判定的。
"片段里出现患者数据" ≠ "本文采集了患者数据"。

**5. 我删错了东西（如实记录）**

整理目录时，我删掉了子agent 留下的构建脚本和一个独立复核脚本，
**没先确认它们有没有用**，而这里不是 git 仓库，**删了找不回来**。
功能上没损失（那个复核脚本的检查项 `precheck_items.py` 全都覆盖了），
但这是我的操作失误，不是谨慎的结果。

## 三、现在需要你做什么：审题（24 道）

**不是标注打分**，是**审题**。区别：

| | 审题（现在） | 标注打分（以后） |
|---|---|---|
| 看什么 | 题目本身**成不成立** | 拿一个 AI 的回答，按标准打分 |
| 判断 | accept / revise / reject | 每条标准给 0 / 1 / 2 |
| 为什么现在做 | 题目不合格就不该进榜 | 要先有 AI 回答才能标 |
| 量 | 24 道题 | 101 条标准 × 2 位标注者 |

### 打开这个文件

`bio-eval/rubric/review/REVIEW_SHEET.md`

每题看 5 件事（表格里也写了）：

1. **情景描述是否忠实于原文**——有没有把作者的结论改写错？
2. **标准是否真的可判定**——换一位专家来打，会不会得到同一个分？
3. **三个锚点是否切得开**——`0`/`1`/`2` 的界线清楚吗，还是凭感觉？
4. **题目是否真的在考推理**，而不是在考"知不知道某个名词"？
5. **如果原文本身没有明显薄弱环节 → 该题应该 reject**（不要为了凑数留）

### 怎么填

编辑 `bio-eval/rubric/review/review_verdicts.jsonl`（24 行，一行一题）：

```json
{"item_id": "R-0001", "verdict": "accept", "comment": "", "reviewer": "你的名字"}
```

- `verdict` 只能填 `accept` / `revise` / `reject`（填 `null` 表示还没看）
- `revise` 和 `reject` **必须在 `comment` 里写清理由**，否则我改不了
- `reviewer` 填你自己，用于留痕

填完告诉我，我会：
1. 跑校验（`--validate`）
2. 按 `revise`/`reject` 的意见改题
3. 把 `review_status` 从 `pending` 推到 `reviewed`——**在这之前这些题不能进入公开榜单**

### 如果你觉得这 24 道太难/太专业

**直接说，这本身是有价值的结果。**

这些题考的是**实验设计与统计推断**（混杂、伪重复、多重比较、幸存者偏倚、
结论超出数据）。你是湿实验背景，对"设计"部分应该有直觉，
但有些点偏生物统计。

如果你标起来觉得吃力，我们要么：
- 换一批更偏**实验设计**、少偏统计的题；
- 或者把这个"吃力"本身记录下来——**它就是"这个 rubric 对领域科学家可用吗"的答案**，
  而这正是本项目要检验的东西之一。

无论哪种，都比硬着头皮标完、得到一个不可信的天花板要好。

### 一个新的、必须说清的局限

上面那个"裁判区分度"检验里，**答案是我让模型写的**（只给题面、不给评分标准，
以免照着得分点凑）。所以它测的是"标准能否区分好答案与敷衍答案"，
**不是**"标准能否区分真实考生的作答"。写答案的和当裁判的还是同一模型家族，
存在**自我偏好**风险。

一句话：**它能证明"分得开"，不能证明"分得对"。** 真正的"分得对"要靠你的审题和
后面的人类天花板。
